## 실행이 잡은 것 (계속)

- **`models.lock`의 tier2/embed 핀이 미설치 플레이스홀더**였다 — `llama3.1:8b-instruct-q4_K_M`,
  `nomic-embed-text` 둘 다 로컬에 없음. Ollama에 실재하는 `exaone3.5:7.8b` / `mxbai-embed-large`로
  정정. `IRREVERSIBLE.md` 변경 이력 기재, 박(PM) 승인. **본편 §34.4 "착수 시 버전 고정" — 고정한
  값이 실재하는지도 확인해야 한다는 실패 사례.**
- **`agent-eval claims add`의 JSONL 스키마** = `{claim_id, developer, scope[], started_at, status}`.
  손으로 쓴 `opened_at`/`note` 필드는 파서가 무시 → `claims list`에 안 뜸. CLI로 생성해야 정본.
- exaone3.5:7.8b는 제약된 enum 분류에서 자유 라벨("Customer Service Issue", "High")을 자주 반환 →
  `classifier._parse`가 unknown을 `other`로 정규화. **v1.0이 v0(튜닝된 규칙)보다 나쁠 수 있음** —
  워크북 서사대로 v1.1(프롬프트 few-shot), v1.2(경계 규칙)로 이어짐.

## 이 결과가 보여주는 것 (Part XI 핵심 사례)

**정확도(+19.7pp, 유의) ↔ Gate C·D 회귀** 를 회귀 게이트가 exit 2로 잡았다.
- 트랙 M: `agent-eval gate ... --baseline-version v0-baseline --fail-on-regression 12` → exit 2,
  "Gate C 0.80→0.20, Gate D 0.89→0.00, p95 0s→15.21s" 를 verbatim 출력. PM이 승격 보류.
- 트랙 C(도현): 같은 상황이면 "정확도 올랐네, 배포" — C·D 회귀를 볼 도구가 없다.

이게 방법론의 값어치다 — "개선"이 다른 축을 무너뜨렸는지 데이터가 말해준다(본편 원칙 2).
동시에 **오버헤드**도 실측됐다: v1 배치 실행 ~15분(실 LLM 33건 × 풀 파이프라인), v0는 <1초.

## CI 회귀 게이트 (본편 §20.4.3)

- `pr-verify.yml`: `--baseline-version current --fail-on-regression 12` — `results/baselines/current.json`이
  저장소에 커밋돼 있어야 발효. 없으면 "No baseline file found — skipping" 후 통과 = 무력.
- `claims audit` CLI는 위반 시 exit 1 (본편 §11). 워크북 초판 Ch 35.1의 "sys.exit 안 함" 서술은 틀림.
