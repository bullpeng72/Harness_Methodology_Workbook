# 저자 관찰 — S8 (두 트랙 동일 채점 · Part XI 비교표 완성)

S0–S7 동안 트랙 M(방법론+AC)과 트랙 C(대조군)를 **같은 목표·같은 모델·같은 캘린더 시간**으로
굴렸다. S8은 마지막 절차 하나다: 두 산출물을 **동일한 골든셋·adversarial 셋으로 사후 1회 채점**하고
9지표 표를 실측값으로 채운다.

## 채점 방식

- 트랙 M: `eval/run_batch.py --golden` → `agent-eval gate` (S3–S7에서 이미 실행, `results/final/v3.json`).
- 트랙 C: `eval/run_baseline.py` (S8 신규). `baseline/triage.py`는 **수정하지 않는다** — 사후 채점만.
  - 트랙 C는 카테고리 3종(`complaint/question/other`)만 낸다. 요구 6종에 **관대 매핑**
    (`complaint→billing`, `question→how-to`, `other→other`) — 대조군에 유리하게.
  - 트랙 C는 우선순위 출력이 없다 → priority 정확도 0%.
  - 트랙 C는 로컬 LLM 경로가 없어(anthropic 전용, 키 없음) 오프라인 스텁으로 돈다.
    인젝션/PII는 "출력 추종률" 대신 **프롬프트 노출률**로 측정 — 티켓 본문이 모델 프롬프트에
    그대로 도달하는지. `baseline/triage.py:26`이 본문을 프롬프트에 직접 삽입하므로 구조적으로 노출된다.

## 트랙 C 채점 결과 (`results/final/track_c.json`, 실측)

```
category_accuracy   : 38.9%  (7/18, 3종→6종 관대 매핑 후)
priority_accuracy   : 0%     (출력 없음)

PII 본문→프롬프트      : 3/4  (리터럴 PII가 있는 케이스 전부)
Gate A~G            : 채점 불가 (자유 텍스트, 스키마 없음)
```

### 표에서 읽히는 것

- **트랙 C가 이긴 지표는 딱 하나 — #1의 착수 속도**(0.5일 vs 문서 먼저). 그 대가로 #2·#3·#4·#6·#7이
  전부 "측정 불가" 또는 무방비다. 빠른 게 아니라 **자를 안 댄 것**이다.
- 트랙 M의 재작업(관문 반려 2회)은 **계획된 비용**이고 커밋·로그로 남는다. 트랙 C의 재작업(롤백 4회)은
  계획에 없었고 DEVLOG 한 줄로만 남는다.
- #4·#6은 방법론의 핵심 주장을 데이터가 뒷받침한 지점이다: 트랙 C는 "정확도 38.9%→올리기"에만
  집중했을 때 인젝션 6/6 노출·회귀 무감지를 **모른 채** 지나간다. 트랙 M은 v1.0에서 정확도가
  올랐지만(p=0.036) 회귀 게이트가 배포를 막았다.
- Gate A~G 채점 자체가 **트랙 C에서는 불가능**하다(자유 텍스트). "측정 가능한 산출물"이 없으면
  비교 자체가 성립 안 한다는 게 첫 번째 관찰이다.
