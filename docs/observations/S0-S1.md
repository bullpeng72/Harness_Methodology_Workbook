## 관문 1 반려가 잡은 것 (본편 §17.1)

박의 반려 R2가 핵심이었다 — 워크북 초판은 Gate F·G를 **대응 요구사항 없이** "정면돌파"했다.
관문을 실제로 밟자 이 구멍이 제출 30분 만에 드러났고, 민수가 실제 필요(상담원이 근거를 봐야 함 /
리뷰어가 답변을 다시 쓰면 안 됨)를 확인해 **ST-008·ST-009**를 추가했다.
→ 이제 A–G 전부 요구사항이 붙었고, `not_measured` Gate는 없다.

R1(측정 불가한 "긴급해 보이는")은 GATE_MAP의 "측정 불가로 반송" 표에 남겼다 — 본편 원칙 1·2가
말하는 "측정 가능해야 증명한다"가 문서로 강제된 지점.

## 가드레일 (본편 §8.4·§34.4)

- dev 프로파일을 이 저장소 세션에 걸었다. `git commit`에서 `rm -rf __pycache__`가 하드코딩 백스톱(`tool_authorization: dangerous_params`)에 걸려 한 번 차단됨 → 캐시는 `.gitignore` 대상이라 `rm` 자체가 불필요했음. **파일 삭제 명령에 `-rf`를 쓰면 개발 세션에서도 백스톱이 문다** — 이건 SPEC-041에서도 유지되는 의도된 동작(파일 *내용*은 스캔 제외되지만 셸 *명령*은 아님). 워크북 Ch 2 사례로 기록.
- runtime 프로파일(`guardrail_profiles/runtime.json`)은 아직 미적용 — S3에서 `eval/`에 배선.
